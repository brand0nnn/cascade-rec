# Shared ranker artifacts

The draft ranker change shares the completed validation evidence and the six selected full-data checkpoints. The exact allowlist is [`results/ranker_artifacts.json`](../results/ranker_artifacts.json): 253 artifacts, about 102.83 MiB in total. Each entry records its repository-relative path, byte size and SHA-256 digest. The manifest excludes itself.

## What is shared

| Evidence | Shared artifacts |
|---|---|
| MLP feature ladder | Seed-0 score, matching, attributes and statistics run records; selected ranks; configurations; summaries; source snapshots |
| MLP repetition | Matching and attributes records for seeds 0, 1 and 2; paired-user and group analysis; numeric tables and figures |
| DIN comparison | Full-data DIN checkpoints and records for seeds 0, 1 and 2; paired comparisons with MLP; group analysis |
| RQ3 | Popularity order, retrieval order, MLP and DIN comparison; aligned ranks; single-thread CPU timing queries; figures |
| Candidate-count sweep | Frozen MLP results for K1 = 50, 100, 200 and 500; per-seed rank/AUC archives; raw CPU timings; reports and figures |
| Score diagnostic | Aggregate training-score audit, sensitivity probe, candidate profiles, examples, reports and figures |

The system comparisons use validation data; the score diagnostic also audits the constructed training lists. The ranker work has not run final held-out Test evaluation. Development samples are kept locally and excluded from research reports.

## Local artifacts and exclusions

The allowlist excludes every other ranker run, including development/sample, invalid, aborted and superseded runs. It also excludes:

- Every `*.log` and every file inside a `.mpl-cache` directory.
- Redundant `validation_groups.parquet` files in the MLP-repeat, DIN-study and RQ3 directories; the K1 sweep copy is shared.
- Nonselected MLP checkpoints outside the six directories listed above.
- `results/ranker_diagnostics/20261025-score-diagnostic/cohort_scores.npz` (the bulk rescored cohort), `demotion_events.csv` and `query_correlations.csv` (individual-event/query audit tables). These remain local and can be regenerated by the diagnostics pipeline.
- Raw/processed datasets, candidate lists, text embeddings and other caches under `data/`.

The small diagnostic `feature_probe.npz`, aggregate profile CSVs, saved timing queries and compact rank archives are shared. Excluded artifacts have not been deleted.

## Reproduction and provenance

Install the project dependencies, then follow the data, text-encoding and frozen-retriever candidate-list steps in [`README.md`](../README.md). The same full-data IDs, temporal split, cached text embeddings and candidate lists are external prerequisites for rescoring or retraining. Candidate lists belong under `data/processed/candidates/two_tower_text_seed0/`; the data itself is too large to share through this change.

Use the current source modules under `src/cascade/` and current configurations under `configs/` for execution. [`ranker_experiment.md`](ranker_experiment.md) records the experiment commands and interpretation. Use fresh run IDs to preserve the saved completed runs. To retrain DIN, first generate a new completed `--sample` run and pass its ID through `--development-run`; sample checkpoints are local prerequisites for that development gate.

Historical `git_hash.txt`, `source_sha256.json` and copied `sources/` files preserve the provenance recorded when each experiment ran. Their bytes are retained. One presentation update is explicit: the K1 `report.md` has a dated interpretation banner; its original bytes are preserved in `report_historical.md`. Saved figures/JSON retain the old heuristic wording and are historical evidence, not a current setting selection. Several source snapshots predate later refactors, so they serve as historical evidence; execution imports the current package. Historical absolute path strings such as `/Users/jingyen/...` identify the original checkout and run locations. They are provenance fields rather than requirements to recreate those directories on another machine. Current execution configurations locate saved runs using repository-relative paths.

The sharing manifest records the bytes actually shared. Its hashes complement each experiment's original manifests; updating current documentation or source code does not rewrite historical snapshots or their recorded hashes.

To obtain the exact artifact paths for staging or inspection:

```bash
python - <<'PY'
import json
from pathlib import Path

manifest = json.loads(Path("results/ranker_artifacts.json").read_text())
for artifact in manifest["artifacts"]:
    print(artifact["path"])
PY
```

This command lists the allowlist. Repository code, configurations, tests and documentation are reviewed and staged separately.
